# LP Rebalancer v0.4.0

Локальный Python-проект для мониторинга и планирования управления позицией
концентрированной ликвидности Uniswap V3 в сети Base. PancakeSwap V3
поддерживается отдельным профилем конфигурации.

## Реализовано

- Подключение к RPC и проверка сети (единый помощник `blockchain.rpc.connect`).
- Чтение состояния пула и выбранной LP NFT-позиции, включая проверку владельца,
  токенов пула и комиссии.
- Однократный мониторинг текущего тика, диапазона, ликвидности и начисленных комиссий.
- Сохранение снимков состояния и решений мониторинга в SQLite.
- Математические расчёты ликвидности и оценка баланса токенов для обмена.
- Расчёт потребности в `token0` и `token1` и проверка достаточности балансов.
- Валидация `RebalancePlan`, включая котировку обмена, минимальный выход
  с учётом проскальзывания и ограничение стоимости газа.
- Проверка запаса ETH на газ перед LIVE-циклом и перед каждой транзакцией;
  ожидание подтверждений receipt с обнаружением реоргов и остановкой watcher
  при неопределённом исходе транзакции.
- Открытие первой позиции (`scripts/open_position.py`): диапазон от текущей
  цены, обмен только избытка одного из токенов и минт NFT из фактических
  балансов кошелька. Необязательный `--amount-usd` ограничивает вложенную
  сумму, оставляя ETH на газ.
- Выполнение цикла (`rebalance_cycle.py`): закрытие позиции, обмен,
  компаундинг через `increaseLiquidity`, сбор комиссий, минт новой NFT и
  burn очищенной NFT после закрытия (`strategy.burn_closed_position`);
  шаги проверяются (`eth_call`) или отправляются в сеть.
- Фоновый watcher (`scripts/watch.py`): тот же цикл по интервалу, lock от
  параллельных запусков, повторные попытки с backoff, ротация логов и
  переключение на новую NFT после LIVE-ребалансировки.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `main.py` | Проверка подключения к RPC (только чтение). |
| `monitor_position.py` | Мониторинг: состояние пула, позиция, комиссии, решение стратегии. |
| `strategy.py` | Решение `HOLD` / `COLLECT_FEES` / `REBALANCE`; `Position` реэкспортируется из `blockchain.positions`. |
| `rebalance_plan.py`, `rebalance_planner.py` | Модель плана ребалансировки и его построение. |
| `rebalance_cycle.py` | Выполнение цикла: шаги, `DRY_RUN`/`LIVE`, отчёт и снимок в хранилище. |
| `scripts/watch.py` | Фоновый запуск цикла по интервалу с lock, логами и backoff. |
| `config.py`, `config.yaml` | Конфигурация; числа стратегии возвращаются как `Decimal`. |
| `blockchain/` | Адаптеры блокчейна: пул, Position Manager, оракул, математика цены и ликвидности. |
| `blockchain/abis.py` | Единственный источник ABI-констант проекта. |
| `blockchain/precision.py` | Общие константы точности (`PRECISION`, `LOG_PRECISION`, `Q96`, `TICK_BASE`). |
| `blockchain/positions.py`, `blockchain/token_balances.py` | Общие модели данных (`Position`, `TokenBalances`). |
| `storage/` | Протоколы хранилища (`interfaces.py`) и реализация на SQLite. |
| `scripts/` | Ручные CLI-инструменты (см. ниже). |
| `tests/` | Автотесты. |

## Скрипты (`scripts/`)

Только чтение, приватный ключ не нужен:

- `python scripts/monitor_pool.py` — вывод состояния пула (тика, цены, ликвидности).
- `python scripts/list_positions.py` — список LP NFT кошелька с диапазонами и ликвидностью.

Проверка ключа (без RPC и транзакций):

- `python scripts/check_wallet.py` — сверяет адрес из `PRIVATE_KEY` с
  `wallet.address`; скрипт завершится с ошибкой при несовпадении.

Отправляют транзакции, нужен `PRIVATE_KEY` в `.env`:

- `python scripts/wrap_weth.py --amount-eth 0.0001`
- `python scripts/approve_weth.py` — без `--amount` выдаёт unlimited allowance.
- `python scripts/mint_position.py --tick-lower <нижний тик> --tick-upper <верхний тик>`
  — границы должны быть кратны tick spacing пула и охватывать текущий тик
  (см. `python scripts/monitor_pool.py`). Скрипт не обменивает токены: балансы
  уже должны соответствовать выбранному диапазону.
- `python scripts/open_position.py` — открывает первую позицию из того, что
  лежит в кошельке: читает пул и балансы, продаёт избыток одного токена,
  рассчитывает ликвидность и минтит NFT. Диапазон по умолчанию берётся из
  `strategy.range_half_width`, `--tick-lower/--tick-upper` задают его явно,
  `--amount-usd 10` ограничивает вложенную стоимость, а `--dry-run` только
  показывает план. Нативный ETH не оборачивается автоматически: если пулу
  нужен WETH, сначала выполните `scripts/wrap_weth.py`; ETH остаётся на газ.

Полный цикл ребалансировки; поведение задаёт `strategy.mode` в `config.yaml`:

- `python scripts/rebalance.py` — в `DRY_RUN` проверяет шаги через `eth_call` и
  готовит остальные, в `LIVE` подписывает и отправляет каждую транзакцию.
  В `LIVE` для обмена нужны `swap_router.address` и `quoter.address`, иначе
  цикл останавливается до отправки транзакций.

Фоновый режим:

- `python scripts/watch.py` — запускает тот же цикл каждые
  `strategy.check_interval` секунд (по умолчанию `5`) и пишет отчёт в консоль и
  `data/watch.log` (ротация: 1 МБ, 5 архивов).
- `python scripts/watch.py --interval 60` — переопределить интервал.
- `python scripts/watch.py --once` — выполнить один цикл и выйти; удобно для
  Windows Task Scheduler или cron.
- `python scripts/watch.py --dry-run` — принудительно включить `DRY_RUN`, даже
  если в `config.yaml` стоит `mode: LIVE`.
- `Ctrl+C` (или `SIGTERM`) завершает watcher после текущего цикла.

Watcher держит `data/watch.lock`: второй экземпляр завершится с кодом `2` и не
будет отправлять транзакции параллельно. Ошибки RPC не останавливают цикл:
задержка между попытками растёт экспоненциально до `--max-backoff` секунд
(по умолчанию `300`). После успешной LIVE-ребалансировки watcher запоминает
`new_token_id` и следующий цикл работает уже с новой NFT; после перезапуска
нужно обновить `position_manager.token_id` в `config.yaml`.

Для автозапуска на Windows создайте задачу в Task Scheduler: программа
`.venv\Scripts\pythonw.exe`, аргументы `scripts\watch.py`, рабочая папка — корень
проекта, триггер — вход в систему или загрузка. Не запускайте одновременно
задачу и watcher из терминала: lock допустит только один процесс.

Скрипты можно запускать и как модули: `python -m scripts.monitor_pool`. При импорте
побочных эффектов нет — ни RPC, ни чтения `.env`, ни обращений к БД.

## Конфигурация

Основные параметры задаются в `config.yaml`: сеть, кошелёк, стратегия и
профили DEX. Сетевые профили лежат в `networks` и ключуются по `chain_id`;
верхнеуровневый `network` выбирает нужный профиль, а `connect()` сверяет
chain id с RPC перед любыми транзакциями. Внутри профиля задаются `rpc_url`,
`weth`, `oracle` и `dexes`.

`rpc_url` может ссылаться на переменную окружения:
`"${BASE_RPC_URL:-https://sepolia.base.org}"`. `.env` рядом с `config.yaml`
загружается автоматически, а fallback используется, если переменная не задана.

Для Base mainnet задайте `network: 8453`, выберите DEX (`dex: pancakeswap_v3`
или `dex: uniswap_v3`) и укажите в `.env` mainnet RPC, например
`BASE_RPC_URL=https://mainnet.base.org`. Профили `8453` уже содержат проверенные
адреса контрактов; для `LIVE` останется пополнить кошелёк и задать `token_id`
существующей позиции либо сначала выполнить mint.

Адреса контрактов сгруппированы в `dexes` по имени DEX (`uniswap_v3`,
`pancakeswap_v3`): для каждого профиля задаются `pool`, `position_manager`
(с опциональным `token_id`), `swap_router` и `quoter`. Ключ `dex` выбирает
один профиль, поэтому переключение DEX — это изменение одной строки;
невыбранные профили не валидируются.

`strategy.range_half_width` — относительная полуширина диапазона
(`0.01` = ±1 %). Числа стратегии парсятся как `Decimal`, поэтому бинарные float
не попадают в расчёты. `weth.address` опционален и по умолчанию равен адресу
WETH в Base. Приватный ключ читается только из `.env`; скрипты проверяют, что
адрес из ключа совпадает с `wallet.address`.

`strategy.burn_closed_position` включает burn очищенной NFT сразу после
`decreaseLiquidity` + `collect` в цикле ребалансировки. В `config.yaml` он
включён, поэтому старые NFT не накапливаются в кошельке; burn стоит газа и
добавляет отдельный шаг в план.

Секция `transaction` управляет защитой LIVE-транзакций:

- `min_eth_balance` — минимальный остаток ETH, который должен сохраниться после
  расчётной стоимости газа всего цикла. Перед первым `send` цикл оценивает газ
  по лимитам всех операций и блокируется, если баланса не хватает; перед каждой
  транзакцией баланс проверяется ещё раз с учётом возможного роста `gasPrice`.
- `confirmations` — сколько подтверждений ждать после блока с receipt
  (`2` = один дополнительный блок). После ожидания проверяется, что receipt и
  его `blockHash` всё ещё находятся в канонической цепи.
- `receipt_timeout_seconds` — сколько ждать receipt и подтверждения. При
  таймауте или реорге watcher останавливается: исход транзакции неизвестен, и
  повторять цикл автоматически небезопасно.

Пустой `oracle.token0_usd_feed` или `oracle.token1_usd_feed` означает, что
соответствующий токен — USD-стейблкоин и оценивается в `$1`; оба фида пустыми
быть не могут. Порядок токенов зависит от сети: на Base Sepolia `token0` — USDC,
а на Base mainnet `token0` — WETH, поэтому ETH/USD фид задаётся для `token0`.

Base Sepolia используется для разработки и тестирования. В пуле Uniswap V3
USDC/WETH ликвидность есть; пулы PancakeSwap V3 на Base Sepolia пока пустые,
поэтому PancakeSwap проверяется на mainnet с небольшим балансом.

## Ограничения текущей версии

- `monitor_position.py` выполняет один проход, а не работает непрерывно;
  непрерывный режим реализован в `scripts/watch.py`.
- Оценка обмена по спотовой цене не является гарантированной исполнимой котировкой.
- `scripts/watch.py` — foreground-процесс, а не системный сервис: для запуска
  после перезагрузки используйте Windows Task Scheduler, NSSM или systemd.
- Реорг обрабатывается в пределах текущего цикла: каждая транзакция ждёт
  подтверждений, а receipt’ы перепроверяются перед следующим шагом. Абсолютной
  финальности нет: если реорг произошёл после возврата из последнего шага или
  после перезапуска watcher, автоматической сверки истории блоков нет.
- Предварительная проверка ETH покрывает расчётный газ цикла и заданный резерв;
  скачок цены газа между проверкой и отправкой может потребовать повторного
  запуска, но транзакция с недостаточным балансом не подписывается.
- `COLLECT_FEES` только компаундит комиссии в ту же NFT; режима «вывести
  комиссии в кошелёк» нет.
- Автоматический выбор новой позиции ограничен текущей конфигурацией:
  диапазон берётся из решения стратегии, а не из оптимизации ликвидности.
