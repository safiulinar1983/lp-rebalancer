# LP Rebalancer — v0.4.0

**Назначение:** открыть первую LP-позицию из произвольного набора токенов и
автоматически сжигать очищенную NFT при ребалансировке.

## Что сделано

- **Планировщик первой позиции:** `position_opener.py` (`OpenPositionPlan`,
  `build_open_position_plan`, `plan_open_position`, `range_ticks_for_pool`,
  `cap_balances_to_usd`). Модуль не делает RPC-вызовов и не отправляет
  транзакции: состояние пула, котировки и подпись передаёт CLI.
- **CLI открытия позиции:** `scripts/open_position.py`.
  - читает текущий тик, `sqrtPriceX96`, балансы `token0`/`token1` и decimals;
  - строит диапазон от `strategy.range_half_width` или принимает явные
    `--tick-lower`/`--tick-upper`;
  - если в кошельке только один токен (или пропорция не совпадает с
    диапазоном), планирует обмен только избытка через
    `plan_swap_to_match_ratio`, получает котировку QuoterV2 и задаёт
    `amountOutMinimum` с учётом `strategy.slippage_bps`;
  - рассчитывает ликвидность и `amount0Min`/`amount1Min` функцией
    `allocate_liquidity` после обмена;
  - `--amount-usd` пропорционально ограничивает стоимость вложенных токенов,
    не трогая нативный ETH, зарезервированный на газ;
  - `--dry-run` показывает план без ключа и без транзакций, LIVE-режим
    использует те же проверки газа, allowance и receipt, что и цикл
    ребалансировки;
  - отказывается работать в LIVE, если для требуемого обмена не настроены
    `swap_router.address` и `quoter.address`.
- **Burn старой NFT:** `strategy.burn_closed_position` включён в
  `config.yaml`. Цикл выполняет `burn` сразу после
  `decreaseLiquidity` + `collect` и до обмена/минта новой позиции. Для burn
  добавлен отдельный газ-лимит `200_000`; шаг виден в плане и отчёте.
- **RPC:** в проекте нет ссылок на конкретного провайдера. Используется
  `${BASE_RPC_URL:-https://sepolia.base.org}` для Base Sepolia и
  `${BASE_RPC_URL:-https://mainnet.base.org}` для Base mainnet; приватный
  endpoint задаётся только через `.env`.
- **Документация:** README обновлён до v0.4.0; добавлены команды
  `open_position.py` и описание burn.

## Ограничения

- `open_position.py` открывает позицию, но не выбирает диапазон по
  оптимизации доходности: диапазон задаётся стратегией или явными тиками.
- При сильном движении цены между котировкой и минтом возможен revert
  проверки slippage; после успешного обмена повторный запуск пересчитает
  позицию по фактическим балансам.
- Burn выполняется только для NFT, которую закрывает текущий цикл; массовая
  очистка старых NFT скриптом не реализована.
